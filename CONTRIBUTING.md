# Як долучитися

Проєкт невеликий і розвивається однією людиною, тому найбільша допомога — точні звіти про помилки та перевірені пропозиції.

## Перед початком

- Питання щодо роботи застосунку — спершу [FAQ](docs/FAQ.md).
- Помилка — [новий issue](https://github.com/terriblefeelings/LocalMonoDonate/issues/new/choose) з версією, кроками відтворення й логом.
- Велика зміна (нова функція, переробка інтерфейсу) — спершу issue з описом мети, щоб не витрачати роботу на непотріб.

## Збірка

Потрібні Rust (stable), MSVC build tools і WebView2 runtime. Node 18+ — лише для HTTP-тестів.

```powershell
cargo build
cargo test
```

Повний посібник зі збірки й пакування — у [README](README.md#збірка-з-вихідного-коду).

## Тести

- `cargo test` — модульні тести Rust.
- `cd AUC; npm install; node _alltest.mjs` — HTTP-перевірки сторінок і API.
- Для тестів не використовуйте власний профіль: задайте `LMD_DATA` на тимчасову теку.

## Правила коду

- Дотримуйтеся стилю й структури, які вже є в проєкті.
- Нові залежності — лише за реальної потреби; аргументуйте в pull request.
- Усі видимі тексти — через систему локалізації (`en` і `ua`), без рядків, вписаних у розмітку.
- Налаштування зберігаються в `%APPDATA%\LocalMonoDonate`; змінюючи `config.json`, передбачте сумісність зі старими файлами.
- Секрети (токени, ключі, `twitch.json`, `streamelements.json`, `.env`) не потрапляють у репозиторій, логи чи скріншоти.

## Pull request

- Одна логічна зміна на запит.
- В описі: що змінено, навіщо, як перевірено.
- Для візуальних змін — скріншот до і після.
- Переконайтеся, що `cargo test` проходить і попередження компілятора не додалися.
